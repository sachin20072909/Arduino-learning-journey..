Signals

30–40 Signals Behind Every Decision

URL-based features

What the address reveals

Length & structure — unusually long or nested paths
Subdomains & TLDs — extra hosts, uncommon endings
Special characters — @, //, encoded tricks
IP instead of domain — numeric hosts
Typosquatting — lookalike brand spellings
Brand similarity — close to known names
Page content features

What the page is asking for

Login forms — password and credential fields
Harvesting cues — urgent “verify account” patterns
HTTP / non-secure — sensitive forms without TLS
Iframes — hidden or nested inputs
Brand mismatch — page claims ≠ actual host
Form behavior — odd destinations and actions
Machine learning · model-selection stage

Small Model. Fast Decision.

The model is trained offline, then shipped with the extension. Inference stays on-device. Final architecture is still being selected.

Candidate A

Gradient-boosted decision tree

  • Strong on tabular URL/page features
  • Compact after training
  • Easier to inspect which signals matter
Candidate B

Compact neural network

  • Small enough for browser runtimes
  • Fast forward-pass on CPU
  • Fits ONNX / TF.js-style export

Privacy by design

Your Data Stays on Your Device.

Traditional cloud detection

Page data leaves the browser

User→ Website info→ Cloud server→ Detection→ Result
  • URLs and content may be uploaded
  • Needs a live network round-trip
  • Privacy depends on a third party
Our approach

Inference never needs the cloud

User→ Website info→ Local ML model→ Result
  • No URL required for inference
  • No webpage content uploaded
  • Works with weaker connectivity
  • Faster local decision-making

Honesty & roadmap

Honest About the Gaps. Ready to Improve.

Current limitations
No reliable live domain-age check without an external service
Focused on web-based phishing, not every scam channel
Advanced attacks can still evade feature-based models
Dynamic pages may change after the first analysis
False positives are possible
Future improvements
Deeper behavioral analysis after load
Stronger typosquatting detection
Optional reputation lists (user-controlled)
Continuous model updates
Richer social-engineering patterns · more browsers
A hackathon-ready core: extract signals locally, score with a compact model, warn before submit. Extras stay optional so privacy remains the default.
